# Life of Colors — public web app

The app that plays Life of Colors puzzles in the browser. Public repo, deployed to GitHub Pages under
`/LifeOfColors_game/`. The puzzles are made by the private sibling repo `LifeOfColors_factory`
(generation, solving, difficulty ranking, level graph, telemetry analysis); this repo holds only what
is needed to run the app and send telemetry. Setup, deploy and the end-to-end workflow: `README.md`
here and in the factory.

Player-facing name: **"Life of Colors"** in every language (`app.title`, `index.html` title/meta).
Active look: the sorcerer theme (no "edition" tagline).

## Tech stack

| Concern | Choice |
|---|---|
| App shell | React 18, Vite 6 |
| Board | Phaser 3, mounted inside a React component |
| Styling | Tailwind CSS 3 |
| Text | i18next / react-i18next — en, de, fr; always starts in German (`src/i18n.js`), the choice is not stored |
| Rules | `src/engine/engine.js` — pure JS, shared by the scene and the tests |
| Telemetry | Supabase (Postgres REST), insert-only, anonymous |
| Tests | Node's built-in runner, `npm test` (no extra dependency) |

## Coding rules

- **Colors** — never hardcode; use named colors in `src/theme.js`. (Exception: a puzzle's
  `name_color` is data.)
- **Strings** — never hardcode visible text; use `t()` and add the key to all three locale files.
  Wording may differ per language, but the consequence in the game must be the same. German says
  "Level" (not "Stufe"); English uses American spelling; terms: "field" (not "cell"), "places"
  (not "sites"), puzzles are "solved".
- **Asset paths** — relative only; `import.meta.env.BASE_URL` for files in `public/`.
- **Fonts and resources** — never load anything from another server. The app font is Arial Black;
  the only bundled fonts are Cinzel (crypt motto) and Mystery Quest (training sign and stamp), via npm
  `@fontsource/*`.
- **Engine** — game rules live ONLY in `src/engine/engine.js`. Any behavior change needs the same
  change in the factory's `instance.py` first, a new export with new golden vectors, and a new
  feature tag if it adds a variation. The scene calls `tap` for every tap, never `applyClick`
  directly.
- **Feature tags** — add a tag to `SUPPORTED_FEATURES` only when fully implemented and tested;
  instances whose `requires` has unknown tags are hidden automatically.
- **Generated files** — `public/catalog/` and `tests/vectors.json` are written by the factory.
  Never edit them, never relax the vector tests.
- **Pure logic is tested** — layout, placement and rule helpers live in plain JS modules without
  React (`engine/*`, `components/map*.js`, `sites.js`, `workshops.js`, `wildcards.js`) and have
  tests in `tests/`. Keep it that way for new logic.
- **Motion** — honor "reduce motion" everywhere: animations stop or are replaced by a still state.
  Map pictures never animate.
- **Mobile first** — portrait phones are the main target; boards up to 9 rows x 6 cols must fit.

## Privacy, telemetry, saved progress

- **Telemetry** collects nothing personal. Only: a random in-memory visit id, app/catalog version,
  env, screens shown (`screen_views`) and per-play data (`puzzle_plays` snapshots: instance id,
  level, pick, counters, rules, visible-time durations, click list). No browser clock times (the
  database's `received_at` is the only clock), no cookies/storage ids, user agent, screen size,
  language, location or referrer. Stars are not sent (derivable from moves). A new field must keep
  these properties and be added to `telemetry/schema.sql` and the factory's `stats_helpers.py`.
- **Saved progress** — `engine/progress.js` is the ONLY code touching browser storage:
  `loc-storage-consent` (the opt-in answer) and, only while that is `granted`, `loc-progress-v1`
  (`{v:2, p:{id: 't'|0..5}, c:{castle: stars}, h:[ids, newest first, max 20], w:[opened places]}`).
  Nothing is stored before the player says yes (ConsentBanner); "No thanks" deletes saved progress;
  without consent progress lives in memory for the visit. Progress is never sent anywhere. Every
  storage access is try/catch — blocked storage must never break the game. Any new stored field
  needs the same opt-in.

## Game model

- **Puzzles** — the app shows `instance.name` (e.g. "Cerulean Gorge"), never the id; telemetry
  sends the id. Name lookups use `normalizeName` (lower case, letters/digits only), identical to the
  factory's `instance_names.normalize_name`.
- **Stars** — `instance.moves_to_win_min` is the best known move count. `starsForWin`: 5 at/below
  the minimum, 2 at 1.4 x minimum, linear in between (rounded), 1 above. Shown only in the win
  animation ("Best: X"); without the value neither is shown. The app never reads `meta`.
- **Start cell** — with `HIDE_START_CELL_IF_NOT_REQUIRED` (on), puzzles with
  `start_cell_required: false` start all-uncolored. Same id either way, so keep this switch fixed.
- **Places (in code: castles)** — the map is the factory's level graph
  (`public/catalog/level_graph.json`): node id = castle number, `layer` = map row, `col` = column,
  paths go one layer up. Castle 0 = the training castle: every instance with `training_position`,
  played in order, done when all are solved. Other ranked instances go to their `instance.site`;
  if not every ranked puzzle has a valid site, they are cut in ranking order into castles 1..n-1
  (harder further up). Without a level graph: one line of `CASTLE_COUNT` castles.
  `instance.level` = castle number (set by `assignCastles`).
- **Unlocking** — castles 0 and 1 are open from the start. Another castle opens when ANY graph
  parent is open and that parent's star counter reaches `UNLOCK_STARS` (20). Star counters: each
  gain in a puzzle's best rating is added to the castle it is in at that moment; counters never go
  down and stay with the castle when puzzles move after an export. When play opens a castle while
  progress is not saved, the consent banner reappears once per visit (nudge).
  `?map=all` opens every castle for review (saves nothing; a note says so).
- **Telemetry `level`** = castle number = graph node id (the factory keeps every exported graph to
  read it).
- **Workshop capacity** — a place never shows more puzzles than its workshop scene has slots
  (34–35): `fitToScenes` drops the surplus (last in ranking order) with a `console.warn`. This is
  only a guard; the factory's export must never trigger it.

## Screens

- **Map** (`CastleMap.jsx`) — draws the whole level graph bottom (training) to top. Places are
  staggered per band and then nudged by `mapLayout.relax` to minimize paths through buildings,
  crossings, overlapping paths and crowding. Open places in color, locked ones grey with a padlock
  (no fog). Place names are not written on the map (tooltip/aria-label only); a badge shows "★ n"
  (✓ when done) once stars are collected; the training castle shows "✓ solved/all", hung under
  the training sign (`trainingGround(...).badge`) instead of under the castle. A locked place
  shows its name and `castles.lockedHint` in a bubble on hover/focus and for `HINT_MS` after a tap
  (so locked places are `aria-disabled`, not `disabled`). Paths are paved with stones
  (`mapPath.pathStones`, deterministic); locked paths are grey, faint, with stones missing;
  overlapping paths give way (`mapClear.giveWay`). Draw order: grass, flat things, paths, standing
  things sorted top-down by their foot, badges. Flat things (fields, ponds) go only on free grass,
  else mirrored or shifted, else left out (`mapClear.placeFlat`). The map opens centered on
  `startCastle` (training castle until done, then the highest open castle) and restores the
  scroll position when coming back.
- **Sites** (`sites.js`) — castle 0 is a castle; levels 1, 2, 3, … cycle through `SITE_ORDER`
  (forest hut, tavern, manor, castle, wizard's tower, windmill, yurt, forest lodge). A site is
  only a look and a name. Each level has its own name: the k-th level of a site takes the k-th entry
  of `siteNames.<site>` (8 per site, same length in every language, max 24 letters). The training
  castle is `castles.tutorial`. Each site has three pictures (open, locked, landscape); in
  `<site>-land.svg` every flat thing is `<g data-flat="box">` and every standing thing
  `<g data-foot="y" data-box="box">` (`parseLand`). Pictures are flat and still, made by an
  external drawing script (not in this repo); only the castle's flag is drawn by the app.
- **Training ground** (`TrainingGround.jsx`) — decorations around the training castle: a wooden
  "Training" sign (Mystery Quest, shrinks long words via `signFont`), cauldron, mirrors with a
  flash, a spilled flask, bow and arrows, practice targets with puzzle emojis, an orc, mushrooms,
  and a chimney with smoke. All are standing things; the castle's own fields make way for them.
- **Place screen** (`LevelScreen.jsx`):
  - *Training castle*: the map button (the workshop's rounded 🗺️) on top, the title, then a
    vertical path of bars (Introduction, Day One … Day Five, then "… and into the wide world …"),
    solved steps with a medal, the next one framed with "Start". Once every day is solved, a green
    rubber stamp "Completed" (`levelScreen.completed`, `stampInk`, in the sign's Mystery Quest, not
    capitals -- friendly, not "rejected"; clean edges with just a few worn spots) sits tilted across
    the title's lower edge, half on it, half below; it lands with a small thump (`stamp-in`).
  - *Other places*: a workshop scene (`Workshop.jsx`, data in `workshops.js`); castle n uses scene
    `(n − 1) mod 6` of hut, cupboard, lab, tower, study, crypt. Flat pictures in the app's navy and
    palette; each puzzle is a potion in its `name_color` — test tube = base puzzle, round-bottomed
    flask = special puzzle; solved = copper medal with the best stars; opened = unstoppered;
    untouched = stoppered; unused slots show empty tubes. Potion details come from the puzzle id
    (`potionLook`, seeded). Picking: the potion lifts and unstoppers, the puzzle opens after
    `PICK_MS`. Header: a copper plate with the place's stars and a bar towards `UNLOCK_STARS`; the
    bar explains itself in a bubble (`castles.starsNeeded*` / `nextOpen*`). The crypt shows the
    motto "Vita Colorum" (Cinzel, worn inscription). New pictures need new numbers in
    `workshops.js` from the same drawing script.
- **Game screen** (`GameScreen.jsx`) — top row: 🗺️ (map), Retry, the place picture (back to the
  place), info button (RulesDialog). Below: puzzle name with its color tile and the move counter.
  Special puzzles' tiles have a wavy white border (`SpecialTile`).
  - *Goal intro*: the goal object blinks briefly (1 s, two blinks) with a pointing hand — in the
    training castle (`INTRO_MS`, not on its first puzzle) and in castles 1..`GOAL_INTRO_LEVELS`
    (now 1: only the first place after the training; `GOAL_INTRO_MS`), when a puzzle is opened,
    not after Retry. Never blocks taps.
  - *Training intro* (`TrainingIntro.jsx`, training puzzle 1 only): four speech bubbles (tap a
    field, the neighborhood decides, the goal, the notebook); the board takes no moves until the
    last one. Not repeated on Retry.
  - *Training notes* (`NoteFlight.jsx`, `TrainingNotes.jsx`): a new rule observation is circled
    and flies into a note card that drops into the notebook (phased: neighbors first, then the
    changed field). The card never covers the tapped field's neighborhood (`noteCardPlace`). The
    board takes no taps while a note flies.
  - *Win* (`WinCelebration.jsx`, mode from `winMode`): `stars` = rising, evaporating stars;
    `full` (5 stars) adds twinkling colored stars; `text` (training or reduced motion) = result box
    only. When a win reaches `UNLOCK_STARS` and opens a locked place, a copper plate comes down on
    chains: "New places unlocked!". The win that completes the training brings the same plate:
    `win.trainingPlate` ("Training complete!"); its result box is the same as every other training day's. After a win the board takes no taps; the player continues with
    Retry or Back.
- **Wildcards** (`wildcards.js`) — a way up for strong players. One locked place on map rows 3, 6,
  8 and 9 (levels 6, 15, 22, 24) carries a wildcard with a fixed challenge puzzle (falls back to the
  place's hardest non-special puzzle if an export moves it). The card on the map (shiny gold, wandering around its spot -- far to the sides,
  a little up and down; still with reduced motion) opens the wildcard scroll. Tapping such a locked place shows the
  usual bubble plus `castles.lockedWildcard` and a card that opens the scroll too; that bubble sits
  lower, covering the map's card. A 5-star win (`WILDCARD_STARS`) opens that place and every place on a lower row; opened
  places are saved in progress `w`, never as stars (open, not done). The game screen shows
  "Wildcard try" and the allowed move count (`wildcard.needMoves_*`).

## Special cells

Schema 1.1, feature tags `special-blocked`, `special-bomb`, `special-mirror`, `special-clock`; one
entry in `board.special_cells`, hashed into the id (a published rule never changes meaning).
Special puzzles are never in the training castle.

- **Rules (frozen, identical to factory `instance.py`)** — blocked and bomb cells count as
  uncolored and ignore taps. A bomb goes off when a tap turns a neighbor into its `trigger` color,
  or on the `taps_to_explode`-th tap on it since the last (re)start (earlier taps only warn); going
  off = Retry (moves reset, the triggering tap is no move). Mirror: the tapped cell's new color
  (from its own neighbors) goes to both cells, no chain. Clock: untappable, starts at
  `cycle[start]`, steps after every tap that changed the board.
- **Tests** — `tests/engine.test.js` replays the factory's special golden vectors. A rule change
  goes through the factory first, then a new export.
- **Scene** — `this.state = { board, bombTaps, hideStart }`; events `specialTap` and `boom`; after a
  boom no taps until Retry remounts the scene. Drawing: blocked = dark hatched hole; bomb = 💣 only
  (never reveal the trigger); mirror = frames, sheen and a dashed line between the two; clock = a
  bulging dial with its cycle's states turning counter-clockwise one step per move. A boom wrecks
  the board and leaves scorch marks.
- **React** (`SpecialOverlays.jsx`) — a bomb, mirror or clock puzzle opens with a ticker line
  (`special.*Intro`) passing twice above the board; the first tap on a blocked or clock field
  explains it; bomb taps show "Oh, careful!"; an explosion shows a BAM starburst (drawn letters, no
  font), a slight jerky tremble, a dust cloud and a Retry button.
- **Telemetry** — unchanged: an explosion is a click with `changed = false`; Retry is a normal
  restart.

## Phaser + React pattern

- `Board` mounts `Phaser.Game` (scale FIT, internal size = board size) and destroys it on unmount.
- The scene emits `boardClick`, `won`, `specialTap`, `boom` on `game.events`; React owns everything
  outside the canvas (buttons, counters, dialogs, telemetry).
- Retry = remount `Board` via a `key` change.

## Branches

- `main` — always stable; every push deploys to GitHub Pages.
- `dev` — integration branch.
- `feature/<short-description>` — one branch per feature.
